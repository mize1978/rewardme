# 開発記録: PURPLE成長ルーム（2026-08-15）

**UX判定: PASS / ROOM EVOLUTION演出: 追加不要**

---

## 何を作ったか

部屋を「買うもの」から「育つもの」に変えた。

タスクの累計完了数が育成段階（`ribbon_stage` 1〜4）を動かし、その段階に応じて
**部屋の絵そのものが差し替わる**。しかも部屋の絵にはリボンちゃんが最初から
描き込まれているため、キャラクターは「配置された素材」ではなく
**その部屋の住人**として存在する。

| stage | tier | 到達条件 | 部屋の状態 |
|---|---|---|---|
| 1 | BASE | 0タスク〜 | ラグの中央にたまごがぽつん |
| 2 | BASE | 10タスク〜 | ベビーリボンが座っている。ソファが増える |
| 3 | COZY | 20タスク〜 | 成長したリボンちゃん。魔法アイテムが増える |
| 4 | DELUXE | 40タスク〜 | 王冠と杖のプリンセス。魔法宮殿 |

---

## 最も重要な設計判断: ROOM EVOLUTION演出を「足さなかった」

実装後、10個目のタスクを完了して実機で体験した結果、**演出の追加は不要**と判断した。

理由は、既存の流れが自然に二段構えになっていたため。

1. 進化オーバーレイが出る → 「ベビーリボンになった！」（キャラのお披露目）
2. 閉じるとページが再描画される → **さっきまでたまごしか居なかった部屋にベビーがいる**（部屋のお披露目）

この二段目が「小さな発見」として機能していた。ここに
`ROOM EVOLUTION!!!` のような説明を重ねると、発見を説明に変えてしまい野暮になる。

> 絵そのものが演出になっているとき、演出を足すのは引き算になる。

判定時に確認したのは3点。すべて意図どおり機能した。

- ✅ 進化オーバーレイ（キャラのお披露目）
- ✅ 閉じた後のBASE／ベビー部屋（部屋のお披露目）
- ✅ 成長ストリップの現在地と✓（歩いてきた道の可視化）

さらに副次的な発見として、**画面全体が一斉に切り替わる**ことが効いていた。
ヘッダー（★Lv.10 ベビーリボン）、右上の成長チェーン（今ここ！）、中央の部屋。
3箇所が同時に「生まれた後の世界」になるため、単一の演出より説得力があった。

## アーキテクチャ

### 拡張しやすさを最優先した

```ruby
# app/models/room_background.rb
GROWTH_ROOMS = {
  "purple" => { prefix: "room_purple_s", stages: [...] }
}.freeze
```

新しいカラーを成長対応にするときは、この定数に1エントリ足すだけ。
判定・画像解決・ストリップ描画はすべてこの定義から導出される。

### キャラの二重表示を防ぐ

成長ルームの部屋画像にはリボンちゃんが描き込まれているため、
従来のキャラ透過PNGレイヤーを重ねると**キャラが2人**になる。

```ruby
def growth_room?
  RoomBackground.growth?(current_room_bg)
end
```

この判定でダッシュボードとショップのミニプレビュー、両方のレイヤーを抑制した。

### 既存機能への影響をゼロにした

- 進化演出は全画面オーバーレイ（別系統）なので**無変更**
- キャラ単体PNG（`stage{N}_{color}.png`）はヘッダーアバター・お手紙・ショップ・
  ログイン・LP など**9箇所で使用中のため存続**
- ショップのカタログサムネは従来の `room_purple.png` を使用（表示崩れなし）
- 成長ルーム以外の部屋（全17件）は従来動作のまま

## 実装前に調査したことで避けた事故

作業開始時、「BLUEに既にある3段階方式をPURPLEにも展開する」という前提で
話が進んでいた。実装前にコードを調査した結果、**その前提が誤りだった**ことが判明。

- `room_blue.png` と `room_blue_royal.png` は成長の前後関係ではなく、
  ショップに並んだ**別商品2件**（FREE / SUPER 1200コイン）
- 部屋を決めるのは `current_room_bg` のみで、`ribbon_stage` を一切参照していない

つまり「BLUEと同じ仕組みに合わせる」のではなく、**どの色にもまだ無い新機能を
PURPLEから作る**話だった。調査せずに着手していたら、存在しない仕様を前提にした
改修が生まれていた。

もう一つ、段階の刻みが**3種類バラバラに存在**していたことも調査で判明した。

| 出どころ | 段階数 |
|---|---|
| `ribbon_stage`（稼働中） | 4段階（0/10/20/40） |
| 新素材の設計 | 3段階（BASE/COZY/DELUXE） |
| 成長ストリップ（ダミー） | 6段階（0-10/11-30/…） |

→ 稼働中の4段階を正とし、**BASEが s1(たまご) と s2(ベビー) の2枚を担当する**
形で整理した。デザイン上は3グレード、育成上は4段階。

## 検証結果

| 項目 | 結果 |
|---|---|
| 部屋画像の解決（s1〜s4） | ✅ 成長ストリップで4枚とも表示・読み込み成功 |
| キャラレイヤーの抑制 | ✅ 成長ルームで非表示、通常部屋で復活 |
| ショップの二重表示 | ✅ ミニプレビューも抑制、カタログは無傷 |
| 進化演出 | ✅ 無変更で正常動作 |
| 実機のstage遷移（s1→s2） | ✅ 10タスク到達で部屋が切り替わることを体験で確認 |
| BLUEへの影響 | ✅ ゼロ（`GROWTH_ROOMS` に未登録のため） |
| 素材サイズ | 4枚合計 約3.4MB（従来 `room_purple.png` 単体で2.4MB） |

## 次の一手

**BLUE / PINK への展開**は `GROWTH_ROOMS` に定義を足すだけで可能。
ただし各色で世界観が異なるため、素材の物語設計は色ごとに必要。

- PINK … お姫様ルート（おうちが豪華になる）
- BLUE … スタールート（星を見上げる子 → アイドルの楽屋）
- PURPLE … 魔法ルート（見習い → 魔法世界のプリンセス）✅ 実装済み

BLUEは stage4 で**部屋そのものが別の場所（楽屋）に変わる**点が他2色と異なる。
「スターになる＝家を出る」という読み替えが成立するため、この差異は維持したい。
